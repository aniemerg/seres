# SimQuery + Simulation Annotations Spec (MVP)

Date: 2026-03-05
Status: Draft for implementation

## Goal

Enable scenario/articles to reference live simulation-derived data (totals, machine replication coverage, runbook markers) without hardcoding values in Markdown.

The system must be:
- deterministic for static builds
- safe (no arbitrary expressions)
- extensible (new query primitives and annotation keys over time)

## Scope

### In scope (MVP)

1. Runbook-driven annotation events:
   - `sim.annotate`
   - `sim.mark`
2. Persisted structured events in simulation event log.
3. SimQuery export artifact (`data/simquery.json`) generated by `sim export-view`.
4. Article directives:
   - inline scalar token: `{{ sim.value ... }}`
   - fenced query block: ```` ```sim-query ... ``` ````
5. Derived machine replication tables:
   - seeded machines (imported machine IDs)
   - produced machines (machine outputs observed in process completion)
   - coverage table (seeded vs produced)

### Out of scope (future)

- Arbitrary expressions or script execution
- Full SQL-like query language
- Server-side querying

## Event Model

### `sim_annotation` event

Fields:
- `type`: `"sim_annotation"`
- `sim_id`: string
- `sim_time_hours`: float
- `key`: string (namespaced recommended, e.g. `scenario.phase`)
- `value`: JSON scalar/object/array (optional)
- `tags`: string[]
- `source`: string (default: `runbook`)
- `metadata`: object
- `timestamp`: wall-clock ISO timestamp (existing event envelope behavior)

### `sim_marker` event

Fields:
- `type`: `"sim_marker"`
- `sim_id`: string
- `sim_time_hours`: float
- `name`: string
- `tags`: string[]
- `source`: string (default: `runbook`)
- `metadata`: object
- `timestamp`: wall-clock ISO timestamp

## Runbook Commands

### `sim.annotate`

Args:
- `sim-id` (optional in runbook when `sim.use` is active)
- `key` (required)
- `value` (optional)
- `tags` (optional; comma-separated string)
- `source` (optional)
- `metadata` (optional JSON object string)

### `sim.mark`

Args:
- `sim-id` (optional in runbook when `sim.use` is active)
- `name` (required)
- `tags` (optional; comma-separated string)
- `source` (optional)
- `metadata` (optional JSON object string)

## SimQuery Export Contract (MVP)

Output file: `data/simquery.json`

```json
{
  "version": "simquery.v0",
  "scalars": {
    "sim.id": "runbook_queue_sequential",
    "sim.summary.total_energy_kwh": 1209372.13,
    "sim.summary.time_hours": 353197.0,
    "sim.summary.process_runs_total": 1641
  },
  "tables": {
    "sim.machines.seeded": [],
    "sim.machines.produced": [],
    "sim.machines.coverage": [],
    "sim.annotations": [],
    "sim.markers": []
  }
}
```

### Table semantics

- `sim.machines.seeded`
  - Machine IDs imported (`import` events) + KB name join.
- `sim.machines.produced`
  - Machine IDs observed in `process_complete.outputs` + KB name join.
- `sim.machines.coverage`
  - For each seeded machine:
    - imported quantity
    - produced quantity
    - `covered` = `produced_quantity >= 1`

## Markdown Directive Contract (MVP)

### Inline scalar

Example:

`Total energy: {{ sim.value key="sim.summary.total_energy_kwh" format="number:2" unit="kWh" }}`

Supported options:
- `key` (required)
- `format`:
  - `number`
  - `number:N` (N decimals)
  - `percent`
- `unit` (optional suffix)

### Block directive

Fenced code with language `sim-query`:

```md
```sim-query
type: table
source: sim.machines.coverage
title: Replication Coverage
columns: [id, name, imported_quantity, produced_quantity, covered]
```
```

Supported block types (MVP):
- `table`
- `two-table`

`two-table` fields:
- `left_source`, `right_source`
- optional `left_title`, `right_title`
- optional `left_columns`, `right_columns`

## Safety and Validation

- Unknown query source renders warning block in article (not crash).
- Unknown scalar key renders inline placeholder (`[unknown:key]`).
- No arbitrary eval.
- Directive parser is strict and key-based.

## Extensibility Plan

1. Add standardized primitives in exporter:
   - inventory at timestamp
   - process runs in interval
   - failures by runbook phase/tag
2. Keep `simquery.version` with additive evolution.
3. Reserve core key namespaces:
   - `sim.*`
   - `scenario.*`
   - `runbook.*`
   - `experiment.*`
